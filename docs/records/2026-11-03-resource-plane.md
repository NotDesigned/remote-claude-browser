# 资源平面：边界修正和后续方向

> 读者：维护者

> 状态：存档。2026-11-03 随项目首次导入时写成（对应上游 0.1.0 之后、本项目 0.2.0 之前），写成后不再修改。原文为英文，移入记录时译成中文。当前设计见 [docs/architecture.md](../architecture.md)。

权威浏览器执行网站，查看端渲染它的投影。这个区分不只适用于 DOM 和输入事件，也必须适用于资源。

```text
权威标签页 ── DOM 事件 ── 标签页自有的 URL 重写器 ── 查看端
     ▲                                                │
     └── 浏览器上下文抓取 ◀── 认证的资源路由 ─────────┘
              │                       │
       object URL 读取器         样式表解析器
              └──────── 有上限的存储 ────────┘
```

## 已完成的边界修正

- 标签页在构造时总是装好资源重写。它不是入口的可选集成点；漏传一个参数也不能悄悄暴露原始 URL。
- 每个标签页拥有自己的重写器和有上限的资源 URL 记忆。重复的图片节点和重新快照复用网关 URL，而不是为每次引用生成新的 HTTP 缓存身份。
- HTTP 资源优先使用浏览器的网络上下文。object URL 从所在的浏览器上下文分段读取，完成或出错时释放持有的对象；它们不会进入无关的直接 HTTP 回退。
- 抓取到的 CSS 是一张资源图：导入、字体和图片相对样式表的 URL 解析，并经同一个网关。压缩和变化的表示头一起处理；解析器的输入有上限。
- 上游的 Cookie 和源控制头不能控制网关的源。认证的字体缓存只对该客户端私有。
- 生命周期集成测试补充组件测试。浏览器验收会阻断查看端直接访问外部；不受限的测试浏览器会自己去取图片，从而掩盖缺失的代理接线。

## 证据和局限

入口漏传了已有的重写器，所以默认的身份阶段把原始图片 URL 直接转发出去。组件测试可以通过，部署出来的组合却是错的。这在基本视图里复现，并在标签页构造处修正。线上预发布检查覆盖了一个公开的图片阅读站首页和阅读页，以及一张浏览器本地的合成图片。这些检查不能证明每个网站都正常。

## 下一步要改进的架构边界

1. 资源生命周期：把缓存新鲜度绑定到文档或运行时的代次，以及上游的校验器；当前磁盘缓存的内存索引在重启后不保留，不是持久的存储索引。设计明确的缓存归属和清理时，保留已有的浏览器配置。
2. frame 归属：资源引用要带上来源 frame 或上下文，以支持跨域 iframe 的 object URL。当前的 object 读取器使用标签页的主 frame；不要声称支持任意 iframe 的 object。
3. HTTP 保真：明确处理重定向后的最终 URL、referrer 策略和 Range 行为。当前的直接 Range 回退不是完整的浏览器网络上下文；图片测试通过不等于视频流可用。
4. 恢复：把 DOM 代次、文档、输入就绪和媒体生命周期建模成一个由会话拥有的投影契约。保留现有的快照和增量恢复机制，不要整体替换能工作的边界。
5. 运行时监管：明确选择部署的是单会话还是托管多会话的组合；测试实际的入口和依赖图。可选的集成接缝不能抹掉生产必需的能力。

不要从换语言、加服务或换框架开始。在构造处修正归属和契约，并测试组装后的系统。
